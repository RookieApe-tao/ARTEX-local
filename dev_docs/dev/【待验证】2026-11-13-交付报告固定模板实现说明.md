# 【待验证】交付报告固定模板实现说明

## 当前状态

实现已调整，等待用户验收真人可读性。最终模型六类合成样本均生成成功；复核仍发现个别草稿使用内部称呼、超出真假响应差异的结论及不适当的 SQL 修复建议。保存校验已拦截内部禁词、逐位读取类结论和关键字过滤等 SQL 修复建议，避免这些草稿直接写入平台。样稿没有访问真实目标，且模型草稿仍需人工阅读；用户确认报告风格与事实边界后，再将此文档改为已完成。

## 本轮调整

- 固定二级标题为“描述、修复建议、测试过程、攻击链路、证据说明”，取消强制三级子标题。权限、定级依据、失败尝试、未验证项和 Burp 复现状态写在自然段中。
- 测试过程固定包含“测试时间”和“执行工具”两行，并说明参数、结果和判据；没有记录时写“未记录”。HTTP 问题写明 Burp Repeater 是否实际使用；未使用时只给建议步骤并标记未验证。并发条件无法由 Repeater 复现时必须说明限制。非 HTTP 问题只写 Burp 不适用，不提 Repeater；协议未确认时标注“协议未确认，Burp Repeater 复测未验证”，不猜协议或给操作步骤。
- 响应头或身份标记不足以证明越权；响应正文缺失时先补证。重复写入建议以唯一约束或幂等处理为先，不补造分布式锁等额外架构。
- 合成身份标记不作为身份凭证，也不建议读者替换标记。SQL 注入修复只建议参数化查询。保存时拒绝约定的内部标签和实验记录用语。
- 兼容草稿接口保持原有六个 JSON 字段和单次模型调用。提示中增加确切输出结构；合成评测不再把同一请求和响应同时放入事实 JSON 与独立报文，避免重复输入。
- 保存校验继续检查报告头、CVSS、固定章节和攻击链，新增执行工具、测试时间和 Burp 状态检查，并拒绝额外层级标题、禁用内部用语及关键字过滤式 SQL 修复建议。自动附加的原始请求、响应及证据完整性校验不变。
- Reporter 仍由 `report_finding` 触发，沿用原有工具和一次保存流程。启动迁移只更新与已知旧默认完全一致的提示词、触发语和工具说明，用户自定义内容保留。

## 固定结构

```markdown
# <系统或模块> <功能或接口> <缺陷>：<实际影响>

CVSS 4.0：<完整 Base 向量> 评分 <分数>（<等级>）

## 描述
<问题、权限条件、实际结果和定级依据>

## 修复建议
<有依据的修复办法和预期行为>

## 测试过程
<实际步骤、Burp Repeater 状态、判据、失败尝试和未验证事项>

## 攻击链路
~~~text
<入口或已知起点>
└─ <请求或命令>
   └─ <观察到的结果>
~~~

## 证据说明
<材料来源和完整性>
```

原始请求、响应和命令由评测器随合成样本附在输出末尾，正文不重复粘贴。实际运行中 ARTEX 自动附加已绑定的 HTTP 流量；非 HTTP 命令按执行记录引用。详细报告仍保留完整测试台账。完整规范见 [交付报告规范](../../docs/交付报告规范.md)。

## 验收

代码变更完成后运行定向 Go 测试、Python 评测工具测试和 `git diff --check`。再使用已授权的当前模型运行六个固定样本，检查字段完整性、重复事实、CVSS、失败记录、Burp 操作、证据原文和攻击链；合成样本不访问真实目标。最终是否通过由人工逐份阅读决定。
