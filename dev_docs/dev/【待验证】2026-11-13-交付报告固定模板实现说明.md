# 【待验证】交付报告固定模板实现说明

## 目标与状态

将单漏洞交付报告固定为面向开发和业务人员的五节结构，补齐发现过程、失败尝试、定级依据、攻击链和 Burp 复现要求。格式由保存入口校验，内容必须依托真实证据；结构合格不代表漏洞结论或复现过程已经通过人工核验。

最近更新：2026-11-16。当前实现统一保留既定五节和必需子标题；同一个 Reporter 先整理事实，再分别完成详细报告和交付报告，最后按证据自查。运行时规范覆盖最终具备保存工具权限的 Agent，自定义数据库提示词继续保留。

本轮 Agent 全包测试、报告相关 Server 定向测试、Python 评测脚本测试和 `git diff --check` 已通过。Server 全包测试受本机未配置数据库的集成用例阻断；没有读取数据库凭据配置。真实模型输出、容器构建与启动仍待验收。

## 固定结构与共享规则

`agent/delivery_report_template.go` 提供共享的章节顺序、保存指引和 `DeliveryReportWritingRules`。默认 Reporter 与兼容草稿生成接口使用同一份写作要求，避免两条路径各维护一套模板。

报告头只保留一个一级标题和一行 CVSS 4.0 信息。一级标题就是漏洞名称，不再重复输出“漏洞名称”字段；向量、分数和等级合并为一行。报告日期使用北京时间；竞态、有效期或先后顺序影响结论时，相关步骤保留必要精确时间，原始时间留在证据元信息中。

报告的二级标题按顺序固定为“描述、修复、测试过程、攻击链路、证据说明”。必需三级标题为“定级依据”“发现过程与攻击思路”“失败尝试与未验证项”“Burp 复现”“复测标准”。攻击链用 `text` 代码块展示有证据支持的步骤。完整原包放在证据说明末尾。

详细报告的逐项测试台账保留工具和参数、判据、时间、观察结果及证据索引。交付报告只保留最短复现步骤和相关结果，正文按“正常查询”“修改后的请求”“操作后的查询结果”等用途名称说明材料，内部编号留在详细台账和原始元信息中。没有复现的结论标为“未验证”；失败尝试按执行记录概述，不补造失败，也不把未完成测试写成排除项。并发与重复提交使用实际业务读回和数量差分，不能仅凭成功状态码判定业务影响。

攻击链使用 `text` 代码块中的简短树形过程，说明实际入口、身份条件、请求、服务端处理和业务结果。只有页面和前端行为有对应证据时才写成前端流程；入口只来自脚本或接口时就从实际调用开始。接口路径单独成行。保存校验要求链路图有起点和至少一个带内容的分支。修复建议只定位已检查的接口、源码、版本和配置；未知路径或版本明确标注，不能推测。面向使用者的完整规范见 [交付报告规范](../../docs/交付报告规范.md)。

## 事实整理、写作与自查

报告 Agent 沿用已有漏洞详情、worker 执行记录和流量证据工具，在同一次报告运行内完成以下工作：

1. 整理已经取得的事实和证据引用。区分实际入口、测试条件、实际观察、潜在影响、失败尝试和未验证项；不为补报告重新探测目标。
2. 详细报告保存逐项台账，确保工具、完整参数、计数、时间、响应和业务核验能够追溯。缺少字段说明缺口，不能从其他测试或文件修改时间补值。
3. 交付报告使用简明描述、必要修复、最短复现、简短树形链路和末尾完整报文。各节依据同一组事实，按用途定位材料，不要求每个链路节点标注内部编号，也不反复抄写参数清单或原始报文。
4. 保存前核对结论与证据是否对应、实际与潜在影响是否分开、页面来源是否真实、计数差分与账号关系是否正确、正文和原包是否重复。格式错误按工具反馈修正，受现有运行预算约束，不无限修订。

该机制继续使用原模型和原 Reporter，不新增 Agent 或独立裁判调用。写作阶段不靠关键词黑名单、正文硬字数上限、证据截断或自动改写原包处理措辞。草稿接口将完整任务材料和流量报文交给模型核对；报告写作规则与保存校验使用同一组章节名称。已保存的历史报告与原始证据不会被批量改写。

## 保存校验与调用兼容

`server/delivery_report_template.go` 的 `validateDeliveryReportTemplate` 校验报告头、固定五节、必需子标题及非空内容，并要求报告头向量与保存参数一致。旧报告按原文展示，不自动改写；新的保存结果统一使用当前结构。Markdown 遍历忽略代码围栏及 HTML 注释中的伪标题，并检查围栏或注释是否闭合；行内 XSS 测试字符串中的注释符不会被当作实际 HTML 注释。

校验接入 `update_finding_report` 工具与 `saveFindingDeliveryReport` 的 HTTP PUT 保存路径，位于自动附包和写库之前。PUT 格式错误返回 400；工具返回可修正的格式反馈。格式错误不覆盖已保存报告。

沿用原生流程：`report_finding` 自动触发 Reporter，读取漏洞、执行记录和流量证据后，通过既有 `update_finding_report` 一次保存详细报告和交付报告。工具名、参数签名、编号约定及证据版本约束不变；不增加人工审批步骤。

运行时按最终工具集判断是否具有 `update_finding_report` 权限。有该工具的 Agent 会收到统一的简短写作与保存规范，包含详细/交付报告的分工、实际入口和证据边界、自查要求及固定格式；流量绑定开关关闭时仍注入。该处理不重新开放被禁用或解绑的工具，也不覆盖数据库中的自定义提示词。

HTTP 报告在“测试过程”中给出 Burp Repeater 的最短可操作复现说明，只保留复现必需的账号或会话、关键参数、操作顺序和判据。原始请求位置与完整性在“证据说明”交代；测试过程已说明的步骤不重复。实际未在 Burp 验证时明确标注“Burp 复测未验证”。非 HTTP 报告说明不适用并提供真实工具操作，不伪造 HTTP 报文。

兼容草稿接口继续返回 `cvss_vector`、`description`、`remediation`、`test_process`、`attack_chain`、`discovery_path` 六个 JSON 字段，字段结构不变。各字段按固定五节及必需子标题组织内容。输入超过模型上下文时由模型接口返回错误，不以静默截断的材料生成结论。

## 默认内容升级

`server/orchestration.go` 在启动时按已知旧内置默认提示词的精确哈希识别可升级记录，并将新版本保留在现有提示词历史中。用户编辑过的提示词不覆盖。默认触发语和工具说明按已知默认内容迁移，自定义描述、schema、工具绑定和启用状态继续保留。

保存期格式要求仍适用于自定义 Reporter 输出。若自定义提示词沿用旧格式，应按工具反馈调整；运行时短规范会解释当前写作和保存约束，数据库原文保留。

## 流量附录与完整性

`appendDeliveryTrafficEvidence` 将已绑定材料附在现有“证据说明”内，使用三级及更低标题，不生成第六个二级标题。每个绑定的请求、响应相邻呈现，每个 `http` 围栏只含一条留存报文；绑定编号、角色、真实采集时间、源流量和地址保留在围栏外的原始元信息中，交付正文按用途名称说明请求及其结果。内部 ID 不变，事实和原包不因写作要求删改。

附录明确平台头部经过整理，不补造缺失协议版本或报文头。正文继续从证据 blob 读取并校验哈希和长度。二进制材料以 Base64 表示时，说明需要还原字节，不能宣称直接粘贴文本即可重放。没有绑定流量不等于任务没有其他原始材料，报告仍须说明本机记录等材料的真实来源。

保留累计 4 MiB 的完整报文上限、证据版本冲突拒绝和损坏材料报错，不以截断片段代替完整包。旧附录通过独立 marker 替换；仅识别代码围栏外独立行 marker，避免响应正文中的同名文本截断报告。

## 前端评分兼容

`web/src/lib/delivery-report.ts` 根据保存的向量生成单行 CVSS 信息，并清理旧报告头中重复的“漏洞名称”与旧版 CVSS 字段；正文和 HTTP 围栏内容保持原样。界面使用本地 `scoreCVSS4Base` 计算评分和等级。漏洞详情页把交付报告单独放在“链路图”右侧的标签中。
