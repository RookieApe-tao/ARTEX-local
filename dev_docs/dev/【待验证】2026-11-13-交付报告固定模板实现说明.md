# 交付报告生成机制改进

## 目标

让开发能快速看清漏洞成立条件、最短复现方法、实际影响和修复办法。详细报告保留完整台账；交付报告减少重复记录，只留下处理漏洞所需的信息。

## 生成流程

- Reporter 先读漏洞节点、执行记录和原始证据，再整理成立条件、实际操作、观察结果、未验证影响和材料位置。旧报告与 worker 总结只作线索，不作结论依据。
- 默认草稿入口由 Reporter 根据原始材料一次生成报告，并在同一次生成中自查事实边界和固定结构；Agent 仍通过 `report_finding → Reporter → update_finding_report` 写入报告。
- `update_finding_report` 不增加模型调用，只执行固定结构、CVSS 向量和证据版本校验，再由平台附加完整流量原文并一次保存详细报告与交付报告。格式错误或证据版本变化时拒绝保存；详细报告不经交付报告写作规则改写。
- 默认提示词、触发消息、工具说明和兼容草稿入口保持一致；启动迁移仅更新已知旧默认，保留用户修改内容。
- 同次自查不增加模型调用，但仍不能保证模型判断正确；离线样本和人工验收用于发现事实、表达及结构问题。

## 固定报告结构

```markdown
# <系统或模块> <功能或接口> <缺陷>：<实际影响>

CVSS 4.0：<完整 Base 向量> 评分 <分数>（<等级>）

## 描述
<问题、成立条件和实际业务结果>
### 定级依据
<权限条件及已观察影响如何支持评分>

## 修复建议
<针对已确认问题的修复办法和预期行为>

## 测试过程
### 发现过程与攻击思路
<最短复现步骤、必要账号或条件、关键请求或命令及判据>
### 失败尝试与未验证项
<影响结论的实际失败和未验证边界>
### Burp 复现
<HTTP 测试说明 Burp Repeater 的实际使用情况；非 HTTP 说明不适用>

## 攻击链路
~~~text
<入口或已知起点>
└─ <请求或命令>
   └─ <观察到的结果>
~~~

## 证据说明
<材料来源、完整性和缺失内容>
### 复测标准
<修复成功时可观察到的结果>
```

## 内容边界

- 测试时间以北京时间显示；仅当先后顺序、竞态或有效期影响结论时，在交付正文保留准确时间。完整时间、工具参数、失败日志、哈希和证据索引放在详细报告。
- 交付报告不要求每次重复列出工具和时间字段。只写最短复现需要的账号、请求或命令、关键参数、顺序和判据；材料没有记录的内容不补造。
- 失败尝试只引用真实执行记录。没有找到撤销工具不能推断为无法恢复；只有文件信息或响应头不能推断已取得内容或已验证权限。
- Burp Repeater 的实际使用情况写在测试过程。HTTP 未使用 Burp 时给出标记为未验证的建议复测步骤；非 HTTP 写实际命令并说明 Burp 不适用。串行重放不能证明并发。
- 攻击链只保留已知功能来源、关键请求或命令及实际结果。页面来源未知时从接口开始，不补造前端操作。
- 已绑定的 HTTP 请求和响应由 ARTEX 原文附加在末尾，正文只引用一次。平台外材料只有在完整留存时才可引用；路径、片段或缺少正文时说明缺口。
- 合成样本明确说明未测试真实目标。身份标记不代表认证凭证。

## 保存校验

保存前检查报告头、固定章节及子标题、CVSS 向量一致性、攻击链结构和证据版本/完整性。保存校验不使用关键词列表评判文风或语义，不硬截断正文、不改写附加的原始证据。

调用仍沿用 `report_finding → Reporter → update_finding_report`，工具名、参数和一次保存两份报告的方式不变。历史报告不批量改写；默认值迁移只处理与已知旧默认完全一致的内容。

## 验收状态

2026-11-16 使用当前配置的 qwen3.8-flash 评测六个固定样本。v26 明确了 JSON 各字段必须包含的子标题后，六例均能生成，章节和子标题检查均通过，预期原文材料也全部找到；但多数正文仍超过 800 字，并出现与证据不符的登录描述、重复的攻击步骤和未被证据支持的影响表述。

v27 进一步要求攻击链保留原始方法与路径、只概述操作和结果。五例生成成功，其中四例通过固定结构检查；IDOR 样本返回了完整 Markdown 而非要求的 JSON，接口以 502 拒绝。未生成成功的样稿没有被当作通过。其余样稿仍有格式和语义问题：有的攻击链缺少关键路径，有的把测试步骤重复成树，有的仍超出正文长度目标。当前提示改进了格式遵循，但不能证明模型已稳定产出可直接交付的真人报告。

所有样本均为离线合成材料，没有访问真实目标。CVSS 向量由样本预先提供，不评估模型独立定级能力；没有同条件旧版基线，不能量化整体相对改进。尚未填写人工评分，因此报告质量未通过人工验收。本说明保留“待验证”状态，最新样稿与失败响应位于本机临时目录 `/tmp/artex-report-eval-v27-concise-chain/`。

默认 Reporter 提示词迁移升级到 v16，仅识别已知完整默认版本，用户自定义提示词不覆盖。本轮兼容草稿入口复用统一写作规范，并明确固定子标题和攻击链字段要求；不增加 Agent、数据库角色或额外模型审阅调用。

## 2026-11-16：拆分草稿格式并兼容完整 Markdown

- Reporter 完整报告继续使用 Markdown 写作规则；草稿接口单独使用 JSON 写作规则，避免同一次请求同时收到“输出整篇 Markdown”和“只输出 JSON”的冲突要求。
- 模型若返回完整五节 Markdown，服务端按标题顺序提取字段；该兼容解析不重试模型、不增加调用。必需子标题若被模型接在正文同一行，服务端会移到独立标题行，再交由原有保存校验检查。
- Reporter 默认提示词和触发消息移除重复写作要求。仅迁移哈希匹配的旧默认提示词和触发消息；已自定义内容不覆盖。
- `tools/report-eval` 从当前源码提取 `DeliveryReportDraftRules`，旧版源码仍回退到 `DeliveryReportWritingRules`。

- Agent 定向测试、报告生成和保存校验定向测试、`go vet ./agent ./server`、评测脚本 10 项单测通过。server 全量测试有数据库依赖用例需要 `ARTEX_PG_DSN` 或本机数据库配置；本轮未读取敏感配置。报告相关测试已单独通过。
- 使用 qwen3.8-flash 对六个固定合成样本各调用一次，共生成 6/6。IDOR 样本返回整篇 Markdown，兼容解析成功；未增加修复调用。模型把两个必需子标题接在正文末尾，服务端行级整理后，六份报告均通过固定标题、子标题和代码围栏结构检查；六份原始合成请求、响应或命令均完整匹配。正文长度为 550–789 字符。
- 结构通过不代表语义合格。人工审阅评分尚未填写；证据不完整样本的修复建议仍偏确定，部分攻击链与测试过程存在重复，需由使用者判断能否直接交付。规范化样稿位于 `/tmp/artex-report-eval-v28-normalized/`，原始模型产出位于 `/tmp/artex-report-eval-v28-format-contract/`。
